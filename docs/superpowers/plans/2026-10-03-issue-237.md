# Issue 237 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct all six release-blocking findings in issue #237.

**Architecture:** Preserve recovery records until an explicit per-function durable delete commits. Bound concurrent watchdog I/O with one deadline. Publish Go envelope headers only after serialization and callback acceptance. Make Helm bootstrap repeatable, enforce singleton upgrades and propagate listening ports.

**Tech Stack:** Java 25/Spring Boot/JUnit 5, Rust/Tokio, Go/httptest, Helm/pytest.

**Spec:** https://github.com/miciav/nanofaas/issues/237 (B1–B6), baseline ef856960e99a6c56b93be6a978965535f7a3eba7.

## Global Constraints

- Single control-plane pod with in-memory scheduler, queues and execution state.
- Preserve existing local changes; work in the managed issue-237 worktree.
- Run GitNexus upstream impact for every existing symbol before modification and detect_changes before completion/commit. The current registered index describes the old checkout; refresh/register the worktree before relying on it, preserving embeddings where present.
- Preserve pending-removal and unavailable recovery semantics and SDK callback reservations.
- Kubernetes E2E belongs to NanoLab; rendering alone does not qualify cluster behavior.

## Review Focus

- Two overlapping deletes: committing A must retain B's recovery record until B commits.
- Catalog save failure: retain recoverable state and rollback visibility, including managed deployment reconciliation failure.
- Child exits while descendants hold pipes: deadline must still terminate the original process group and release readers.
- Callback rejection: runtime error carries no envelope encoding, marker, application headers or stale content type.
- Partial demo bootstrap and transport/server failures: replay converges without swallowing errors or overwriting user changes.
