**Files:** `control-plane/.../deployment/DeploymentProviderResolverTest.java` (4: lines 39,53,106,118), `control-plane/.../deployment/ManagedDeploymentFallbackTest.java` (70), `control-plane/.../registry/FunctionServiceManagedDeploymentTest.java` (114), `control-plane/.../service/InvocationExecutionFactoryTest.java` (88), `control-plane/.../service/InvocationServiceDispatchTest.java` (440,670,694,718), `control-plane/.../service/InvocationServiceRetryTest.java` (272), `control-plane/.../service/ReactiveInvocationCoordinatorOffloadTest.java` (3), `modules/container-deployment-provider/.../ContainerLocalDeploymentProviderTest.java` (4), `modules/container-deployment-provider/.../DockerJavaContainerRuntimeAdapterIntegrationTest.java` (1), `modules/image-validator/.../KubernetesImageValidatorTest.java` (4), `modules/k8s-deployment-provider/.../KubernetesResourceManagerTest.java` (3), `modules/offload/.../DefaultOffloadGatewayTest.java` (5), `sdks/java-lite/.../NanofaasRuntimeTest.java` (1), `sdks/java/.../runtime/HandlerRegistryTest.java` (3).

**Pattern:** a lambda inside `assertThatThrownBy(...)` / `assertThatCode(...)` / `catchThrowable(...)` contains MORE THAN ONE method invocation that can throw a runtime exception. The rule requires exactly one.

**Fix shape** (hoist all but the last invocation out of the lambda):

```java
// BEFORE
assertThatThrownBy(() -> gateway()
        .invokeRemote(task(spec), OffloadTrigger.EAGER, OffloadContext.none(), BUDGET_MS)
        .block())
        .isInstanceOf(OffloadFailedException.class);

// AFTER
OffloadGateway gateway = gateway();
InvocationTask invocationTask = task(spec);
assertThatThrownBy(() -> gateway.invokeRemote(invocationTask, OffloadTrigger.EAGER, OffloadContext.none(), BUDGET_MS)
        .block())
        .isInstanceOf(OffloadFailedException.class);
```

Rules of thumb for choosing what to hoist:
- Hoist every invocation in the lambda except the final one whose thrown exception is the assertion subject.
- Pure value constructions (`task(spec)`, `new X(...)`, `FunctionSpec(...)`) hoist too — the lambda must contain exactly ONE call chain that can throw.
- When the lambda builds a fluent chain ending in `.block()` / `.execute()` / the throwing call, keep only that chain inside.
- When the lambda already contains a single call but with intermediate pure steps that Sonar counts (e.g. `client.send(request, ...)` after `client.build()`), hoist the builder.
- Never change the assertion subject, the exception type/message assertions, or any mock/stub setup. Tests must still pass unchanged.

### Task 7: S8786 regex backtracking (3) + S6885 Math.clamp (3)

**S8786 — simplify regexes with super-linear backtracking:**
- `modules/container-deployment-provider/.../ContainerLocalDeploymentProvider.java:256` — in `normalizeName`: the `replaceAll("-+$", "")` and `replaceAll("^-+", "")` steps are O(n²) on runs of dashes.

Fix shape — possessive quantifiers preserve the matched language for anchored/simple patterns (verify each site):
```java
.replaceAll("-+$",  "")  →  .replaceAll("-++$", "")    // possessive: $ anchor is deterministic
.replaceAll("^-+",  "")  →  .replaceAll("^-++", "")    // possessive: ^ anchor is deterministic
.replaceAll("-{2,}", "-") → .replaceAll("-{2,}+", "-") // possessive quantifier
.replaceAll("[^a-z0-9-]", "-") → .replaceAll("[^a-z0-9-]+", "-") // quantify; identical because a following -{2,} replace compacts runs
```
Apply the possessive form ONLY to the flagged lines. For `[^a-z0-9-]` → `[^a-z0-9-]+`: only if a subsequent `-{2,}`/`-+$` compaction in the SAME chain makes the results identical (verify in `normalizeName` and `validationPodName` — both have `-{2,}` compaction after). If the flagged regex is a different one at the flagged line, read it and apply the same principle: make the quantifier possessive/atomic or restructure so no super-linear backtracking remains, preserving the exact matched language.
